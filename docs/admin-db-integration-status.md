# 관리자 기능과 공용 DB 연동 확인 사항

확인일: 2026-09-28 (한국 시간)

## 구현 및 검증 상태

- 관리자 API 권한 검사와 PC·모바일 관리자 메뉴 연결을 main에 반영했다.
- 관리자 공고 목록·색인 상태 조회 API를 반영했다: e13b2a3.
- 관리자 공고 점검 화면과 API 호출 연결을 반영했다: a2bc1fe.
- 관련 백엔드 테스트 63개가 통과했다. 실제 공용 DB 연동 성공을 의미하지는 않는다.
- 프론트엔드 변경 파일의 ESLint 및 git diff --check를 통과했다.
- 브라우저에서 공고 조회 실패 안내가 표시되는 것을 확인했다.
- 실제 공고 목록·색인 상태 표시와 페이지 이동은 아직 검증하지 못했다.

## 로컬 연결 환경에서 확인된 문제

연결된 Supabase 프로젝트:
https://skhtvbxajhsgmjalnbxo.supabase.co/

백엔드 클라이언트로 읽기 전용 조회를 수행한 결과:

| 조회 대상 | 결과 |
| --- | --- |
| users.user_id | 42703: 컬럼 없음 |
| users.auth_id | 조회 성공 |
| public.contests | PGRST205: API 스키마 캐시에서 테이블을 찾지 못함 |
| public.contest_embeddings | PGRST205: API 스키마 캐시에서 테이블을 찾지 못함 |

- 최신 팀 코드는 users.user_id를 사용하므로 현재 연결 DB와 구조가 일치하지 않는다.
- 관리자 AI 로그 API는 200을 반환했다.
- 관리자 공고 API는 503을 반환했다.
- 공고가 0개인 상태가 아니라 API에서 필요한 테이블을 찾지 못하는 상태다.
- PGRST205만으로 실제 테이블 부재와 스키마 노출·캐시 문제를 구분할 수는 없다.

## 필요한 후속 확인

1. 팀 공용 Supabase 프로젝트와 위 로컬 연결 주소가 같은지 확인한다.
2. 주소가 다르면 공용 프로젝트에 맞는 로컬 환경변수를 설정한다.
   비밀키는 저장소나 문서에 기록하지 않는다.
3. 주소가 같으면 실제 테이블·컬럼, 마이그레이션 적용 상태와 API 노출 상태를 확인한다.
4. 환경변경 후 백엔드를 재시작하고 프로필 조회를 재검증한다.
5. 관리자 공고 목록·색인 상태 표시와 페이지 이동을 실제 데이터로 검증한다.

공용 환경 확인 전에는 이 문제를 우회하기 위해 코드를 auth_id로 되돌리거나
테이블·컬럼을 임의로 생성·변경하지 않는다.
