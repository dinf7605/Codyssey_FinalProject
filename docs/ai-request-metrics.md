# 학습 분해 AI 요청 계측

## 이번 변경

- `decompose_goal`의 일반 루프와 최종 재시도를 포함한 실제 Messages 요청을 기록한다.
- 동기·스트림 라우터가 같은 분해 함수를 사용하므로 양쪽에 적용된다.
- 기존 처리 기록 `ai_call_logs`와 일별 관리자 통계는 유지한다.
- 새로운 `ai_request_logs`는 AI 요청 한 번에 한 행이다. 도구 실행 횟수와 다르다.
- 요청별 성공·실패, 오류 분류, 요청 시간, 모델, 응답에서 제공한 토큰 수를 기록한다.
- `outcome`은 해당 분해 실행의 최종 결과(agent/partial/template/error)다.
- 요청 자체가 성공해도 결과 JSON 검증에 실패할 수 있다. `succeeded`는 요청 예외 발생 여부이며 최종 계획 품질의 성공률이 아니다.
- 키가 없거나 시간 예산이 부족해 AI를 호출하지 않으면 행을 만들지 않는다.
- usage 누락·음수·잘못된 값은 NULL로 남긴다. 0원·0토큰으로 추정하지 않는다.
- 캐시 생성·읽기 토큰은 일반 입출력 토큰과 구분한다.
- 프롬프트, 응답 본문, 오류 본문, 사용자 식별자는 기록하지 않는다.

## 적용 순서

1. 팀 최신 main을 작업 브랜치에 합친다. 팀 채널에 015 사용을 알리고 번호가 중복되지 않는지 확정한다.
2. `backend/migrations/015_ai_request_logs.sql`과 코드·테스트를 함께 검토한다.
   로그 기본키는 DB가 생성하는 bigint identity이며 클라이언트는 id를 보내지 않는다.
   created_at은 요청 시작 시각을 보내고, DB 기본값은 now()다.
   사용자 식별자가 없는 전역 운영 로그이므로 user_id는 저장하지 않는다. 관리자 전용 API에서만 조회한다.
3. backend에서 `python -m pytest -q`를 실행한다. 공용 main에 올릴 변경은 SQL과 코드·테스트를 함께 포함한다.
4. 팀 절차에 따라 브랜치를 push하고 담당 C에게 공용 DB 적용을 요청한다. 개인 DB 데이터는 옮기지 않는다.
   동일 구조에서 재실행할 수 있도록 IF NOT EXISTS를 쓴다. 기존 UUID 기본키 구조가 발견되면 중단한다.
   다른 기존 구조 차이가 있다면 담당 C가 검토한다. 각자 SQL Editor에서 실행하지 않는다.
5. 담당 C가 적용 기록 및 Advisors 결과를 확인한 뒤 backend/README.md의 migration 표에 적용 내역을 추가한다.
6. 적용 확인 후에만 루트 .env의 AI_REQUEST_METRICS_ENABLED=1로 활성화하고 백엔드를 재시작한다.
   그 전에는 0을 유지한다. 키 값은 코드·커밋·문서에 넣지 않는다.
7. 학습 계획 생성 후 실제 요청 저장·관리자 통계를 확인한다.

## 집계 기준과 남은 작업

- 요청 실패율 = 저장된 실패 요청 수 / 저장된 전체 요청 수. 분모 0이면 미집계다.
- 같은 run_id의 행들은 한 번의 학습 분해에 속한다. 각 행의 outcome은 동일하므로
  템플릿 대체율을 계산할 때는 행 수 대신 run_id별로 중복을 제거해야 한다.
- 이번 기록 대상은 학습 분해만이다. 추천(goal_recommender), 재계획(replan)은 아직 미포함이다.
- 관리자 API·화면 연결은 구현됐으며 공용 환경 확인이 남았다. 게이트웨이 단가 확인과 비용 제한은 후속 작업이다.
- Anthropic 공개 단가를 게이트웨이 청구액으로 간주하지 않는다.
- 응답을 받지 못한 요청의 과금 여부는 알 수 없다. 캐시 상세 요금·할인·서버 도구 요금도
  이 기록만으로 확정할 수 없으므로 비용은 계산하지 않는다.
- 기록은 분해 루프 종료 후 DB 한 번 호출로 저장하므로 기록 저장 시간이 요청 완료에 추가된다.
  루프 중에는 DB를 호출하지 않는다. 저장 실패는 계획 생성을 실패시키지 않으며
  서버에 고정 경고만 남긴다. 프로세스 종료·저장 실패 시 일부 기록이 빠질 수 있다.
- 기존 과거 기록에서 요청 수나 실패율을 복원하지 않는다.
- 롤백: 환경변수를 지우거나 0으로 바꾸고 백엔드를 재시작하면 추가 DB 저장이 중단된다.
