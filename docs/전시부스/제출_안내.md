## 제출 전에 팀이 정해야 할 것

1. **팀원 이름 표기** — `이 민`은 README 표기(사이 띄움)를 그대로 썼다. 본인에게 확인.
2. **영상 자료** — 스탠바이미로 무엇을 틀지 정한다. 후보: 서비스 시연 녹화 영상 / 발표자료(`docs/발표자료_StudyPace.pdf`) 슬라이드 / 노트북을 연결한 실시간 시연. 정하면 파일 형식 · 재생 방식 · 연결 방식(USB · HDMI · 화면 공유)을 신청서에 적는다. 안내문은 노트북 · 케이블을 팀이 갖고 있는지도 확인하라고 한다.
3. **추가 필요 물품** — 실시간 시연을 하면 노트북용 전원(멀티탭)이 필요한지 정한다.
4. **팀 로고** — 저장소에 로고 파일이 없다. 있으면 원본을 따로 제출하고, 없으면 "로고 없음"으로 알린다.

## 알아 둘 점

- **서비스 화면 캡처 해상도** — `docs/screens` 의 화면은 660 × 721 px 이다. 구성안 크기(약 145 mm 폭)로 출력하면 115 dpi 정도로, 대형 출력물로는 쓸 수 있지만 가까이서 보면 선명하지 않다. 더 선명하게 하려면 배포 주소에서 같은 화면을 2~3배 배율로 다시 찍어 `images/` 의 같은 이름 파일을 바꾸면 된다 (Chrome 개발자 도구 › 기기 툴바 › DPR 3 › 「스크린샷 캡처」).
- **헤더 배경** — 서비스 표지 그림(`frontend/public/learning-path-blue.png`)의 오른쪽을 잘라 합성했다. 원본도 `images/` 에 함께 넣었다.
- **글꼴** — 구성안은 어느 PC 에서나 같게 보이도록 `맑은 고딕`을 썼다. 서비스 화면의 글꼴은 서울남산체(`frontend/app/fonts/`)이며, 디자인 시안에 쓰고 싶다면 이 글꼴 파일을 함께 보낸다.
- **수치의 근거** — 가동률 100% · 외부 점검 25회 · 서버 오류 0건: `docs/ops-report.md` / 일정 배치 규칙 위반 0건: `backend/evals/RESULTS.md`(일정 실현 가능성) / 실사용자 5명 · 5일: `docs/user-test/리포트.md` / 테스트 546개 · 점검 12회: `README.md`.
