# StudyPace 프론트엔드

Next.js 16 (App Router) + React 19 + **JavaScript**
모바일이 주력이므로 모바일 화면을 기준으로 만들고 데스크톱에서 넓히는 방식이다.

## 실행

```bash
cd frontend
npm install
npm run dev     # http://localhost:3000
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 배포용 빌드 |
| `npm run lint` | ESLint 검사 — TypeScript를 안 쓰는 대신 이게 안전망이다 |

> `next lint` 명령은 Next.js 16에서 제거됐다. `npm run lint`가 `eslint .`를 직접 부른다.

### 환경변수

`frontend/.env.local` 을 만들고 백엔드 주소를 넣는다. (`.env.local`은 커밋되지 않는다)

```
NEXT_PUBLIC_API_BASE=http://localhost:8000
```

배포할 때는 **Vercel 대시보드에도 같은 값을 등록**해야 한다.
빠뜨리면 "로컬에선 되는데 배포하면 안 되는" 상황이 된다 (`docs/학습로드맵.md` 6-②).

│       ├── study/             학습 타이머

│   ├── GrowthPreview.js       레벨별 화면 확인용 (배포 전 제거)
│   ├── Icon.js                선 아이콘 (기호 문자 대신)
│   └── ...

`(app)` 처럼 괄호가 붙은 폴더는 **URL에 나타나지 않는다.** 레이아웃만 공유하기 위한 묶음이다.
`app/(app)/dashboard/page.js` → `/dashboard`

## 화면 크기별 구조

모바일이 주력이지만 PC도 **모바일을 넓힌 화면이 아니라 별도 구조**로 만들었다.

| 폭 | 내비게이션 | 본문 |
|---|---|---|
| ~899px | 하단 탭 4개 | 한 기둥 |
| 900px~ | **왼쪽 사이드바** (상단 막대·하단 탭 숨김) | 한 기둥, 폭 1000px 가운데 정렬 |
| 1160px~ | 왼쪽 사이드바 | **2단** — 왼쪽 오늘·진도, 오른쪽 기록·잔디·패턴·공모전 |

- 내비 항목은 `lib/nav.js` 한 곳에 정의하고 `BottomNav`·`SideNav`가 같이 쓴다. 한쪽만 고쳐서 어긋나는 일을 막는다.
- 온보딩·로그인·가입은 집중이 필요한 흐름이라 PC에서도 **520px 좁은 기둥**을 유지한다(`.focus`).
- 랜딩은 PC에서 히어로와 일정 미리보기를 **나란히** 두고 문답을 2단으로 편다.
- hover 효과는 `@media (hover: hover)` 안에만 둔다 — 터치 기기에서 눌린 상태가 남지 않게.

## 모바일 대응

| 항목 | 처리 |
|---|---|
| 노치 · 홈바 | `viewportFit: cover` + CSS `env(safe-area-inset-*)` |
| 터치 타깃 | 버튼 최소 높이 48px |
| 입력 확대 방지 | `.input` 글자 크기 16px — iOS는 16px 미만이면 포커스 시 화면을 확대한다 |
| 확대 허용 | `maximumScale: 5` — 확대를 막지 않는다 (접근성) |
| 가로 스크롤 | `body { overflow-x: hidden }` + 칩 줄은 `.scroller`로 개별 스크롤 |

## 디자인 토큰

색·간격·글꼴은 전부 `globals.css` 상단의 CSS 변수로 관리한다.
**개별 컴포넌트에 색을 직접 쓰지 않는다** — 다크 모드가 깨진다.

```css
color: var(--ink-2);        /* 좋음 */
color: #4E5866;             /* 나쁨 — 다크 모드에서 안 보인다 */
```

### 항상 보이는 것 vs 쌓아야 열리는 것

| | 예 | 왜 |
|---|---|---|
| **항상 보인다** | 목표명 · 마감일 · **D-Day** · 이번 주 학습시간 목표 | 사용자가 직접 넣은 값이다. 이 서비스가 답하기로 한 질문("기한 안에 끝낼 수 있나")이 여기 있으므로 첫 화면에 둔다 |
| **쌓여야 열린다** | 진도 신호등 · 학습 잔디 · 시간대 패턴 | 며칠치 기록이 있어야 계산되는 값이다. 기록 없이 보여주면 빈 그래프가 된다 |

프로필 요약(`ProfileSummary`)이 대시보드 맨 위에 고정으로 들어가고,
PC에서는 사이드바 하단에도 목표와 D-Day가 함께 보인다.

### 적응형 UI — 쓸수록 채워진다 (`FR-UI-01` · `FR-UI-02`)

누적 학습시간이 레벨을 정하고, 레벨이 **무엇을 보여줄지**를 정한다 (`lib/growth.js`).

| 레벨 | 조건 | 새로 열리는 것 |
|---|---|---|
| 1 입문 | 0시간 | 오늘의 학습만 |
| 2 초급 | 10시간 | 연속 학습 기록 |
| 3 중급 | 30시간 | 진도 신호등 · 공모전 추천 |
| 4 상급 | 80시간 | 학습 잔디 · 시간대별 패턴 |
| 5 최상급 | 150시간 | 학습 습관 분석 |

**기록이 없는 사람에게 빈 그래프를 보여주지 않는 것**이 핵심이다.
처음엔 오늘 할 일만 있고, 쌓이는 순서대로 구역이 열린다.
대신 다음에 무엇이 열리는지는 항상 보여준다 — 그게 없으면 그냥 기능이 없는 화면으로 읽힌다.

`<html>`의 `data-level`(1~5)과 `data-density`가 강조색과 여백 배율도 함께 조절한다.
레벨이 올라가도 **명도 대비는 유지**한다 (`NFR-A11Y-01`).

레벨별 화면은 대시보드 상단의 **미리보기 선택기**로 확인할 수 있다.
`components/GrowthPreview.js` — 개발·발표용이므로 **배포 전에 제거**한다.

## 디자인 원칙

1. **모든 것을 카드로 감싸지 않는다.** 테두리·그림자를 전부에 찍으면 위계가 사라진다.
   구역은 규칙선(`.sec-head`)으로 나누고, 카드(`.panel`)는 정말 떠 있어야 하는 것에만 쓴다.
2. **하루는 끊어진 카드가 아니라 이어진 시간 축으로 보여준다** (`DayTimeline`).
3. **아이콘은 SVG로 그린다.** 기호 문자(◉ ▦ ◈)는 기기·폰트마다 달라지고 미완성처럼 읽힌다.
4. **색은 학습 기록에만 쓴다.** 화면 자체는 잉크와 종이로 두고, 공부한 만큼 색이 생기게 한다.

## 지켜야 할 것

1. **AI가 만든 내용에는 `AiBadge`와 `AiNotice`를 반드시 붙인다** (`NFR-ETHIC-01`)
   숨김·접기 기능을 넣지 않는다.
2. **상태를 색으로만 구분하지 않는다** (`NFR-A11Y-01`)
   진도 신호등도 색 + 문구를 함께 쓴다.
3. **빈 상태를 비워두지 않는다** — `EmptyState`로 다음 행동을 제시한다.
4. **에러를 삼키지 않는다** — `lib/api.js`가 실패 사유를 던지면 화면에서 보여준다.

## 지금 상태

- 화면과 흐름은 전부 만들어져 있고 **데이터는 `lib/mock.js`의 예시값**이다.
- 백엔드가 붙는 순서대로 `lib/api.js` 호출로 바꾸면 된다.
- 로그인·가입 폼은 화면만 있고 제출 동작은 아직 연결되지 않았다.
